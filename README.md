# School Result Management System API

## Overview

The School Result Management System is a backend API built for managing student academic records, term-based examination results, score updates, and student administration.

The system is designed with:

- Clean service separation
- Academic term validation
- Result finalization protection
- Atomic score updates
- Session and term consistency
- Auto-generated student registration numbers
- Natural language student search
- Scalable MongoDB structure
- Automated term finalization via cron job

This project uses:

- Node.js
- Express.js
- TypeScript
- MongoDB
- Mongoose
- node-cron

---

# Features

## Student Management

- Register new students with auto-generated registration numbers
- Natural language search (e.g. "boys in JSS1", "graduating students")
- Filter by class, gender, active status
- Sort by age, date added
- Count queries (e.g. "how many girls")
- Pagination support
- Update student records
- Fetch by MongoDB ID or student registration number

## Result Management

- Create student results
- Update subject scores
- Add new subject scores
- Fetch all student results with total score and average
- Fetch result by ID
- Fetch result by registration number
- Fetch result by term and session
- Best student per term
- Best students per session (top 10 leaderboard)

## Academic Term Control

- Academic session management
- Term management with offered subjects
- Result finalization protection
- Prevent updates after term finalization
- Automated term finalization via cron job (runs daily at midnight)

## Safety Features

- No delete functionality
- Protected finalized results
- Centralized exam validation
- Compound academic filtering using session, term, and studentId

# Database Design

## Student Model

The Student model stores student personal and academic information.

### Example Structure

```json
{
  "studentId": "CHI/2026/001",
  "name": "Chinedu Okafor",
  "class": "JSS1",
  "gender": "male",
  "dob": "2012-03-15T00:00:00.000Z",
  "isActive": true,
  "parentsContact": {
    "name": "Emmanuel Okafor",
    "phone": "08012345678",
    "email": "emmanuel.okafor@gmail.com",
    "relationship": "father"
  },
  "studentFile": "https://cloudinary.com/..."
}
```

### Student ID Format

Student registration numbers are auto-generated by the system:

- First 3 letters of student name
- Year of admission
- Sequential number per year

---

## Result Model

The Result model stores student academic results per term per session.

### Example Structure

```json
{
  "studentId": "CHI/2026/001",
  "name": "Chinedu Okafor",
  "term": "first",
  "session": "2026/2027",
  "scores": [
    {
      "subject": "Mathematics",
      "score": 85,
      "teacherId": "TCH101"
    }
  ]
}
```

---

## Term Model

The Term model controls academic state.

### Responsibilities

- Stores academic sessions and terms
- Tracks offered subjects per term
- Controls result finalization
- Prevents editing finalized results
- Supports automated finalization via cron

### Example Structure

```json
{
  "session": "2026/2027",
  "term": "first",
  "offeredSubjects": ["Mathematics", "English Studies", "Literature"],
  "startDate": "2026-09-01T00:00:00.000Z",
  "endDate": "2026-11-30T00:00:00.000Z",
  "isFinalised": false,
  "isActive": true
}
```

---

# Result Finalization Logic

The system uses centralized exam validation.

Before creating or updating results:

1. The system checks if the term exists
2. The system checks if the term is finalized
3. If finalized, all write operations are blocked

The cron job runs every day at midnight and automatically finalizes any term whose end date falls within that day.

This ensures academic integrity.

---

# Average Calculation

Averages follow the Nigerian grading standard:

- Divides by total offered subjects, not subjects written
- Schools enter considerate scores for absent students
- Ensures fair comparison across all students

## Natural Language Search

Search students using natural language queries.

### Endpoint

```http
GET /student/search?q=boys in JSS1
```

### Supported Queries

| Query                    | Result                           |
| ------------------------ | -------------------------------- |
| `boys` / `male`          | Filter by gender male            |
| `girls` / `female`       | Filter by gender female          |
| `active`                 | Filter active students           |
| `inactive` / `suspended` | Filter inactive students         |
| `graduating`             | Filter SS3 students              |
| `junior graduating`      | Filter JSS3 students             |
| `senior students`        | Filter SS1, SS2, SS3             |
| `junior students`        | Filter JSS1, JSS2, JSS3          |
| `senior boys`            | Senior male students             |
| `junior girls`           | Junior female students           |
| `in JSS1`                | Filter by specific class         |
| `named john`             | Search by name                   |
| `youngest`               | Sort by date of birth descending |
| `oldest`                 | Sort by date of birth ascending  |
| `recently added`         | Sort by creation date descending |
| `how many boys`          | Count male students              |
| `how many in JSS1`       | Count students in class          |

### Query Parameters

| Parameter | Type   | Description                    |
| --------- | ------ | ------------------------------ |
| `q`       | string | Natural language search query  |
| `page`    | number | Page number (default: 1)       |
| `limit`   | number | Results per page (default: 10) |

# Validation Rules

## Student Rules

- Registration number is auto-generated — not accepted from request body
- Date of birth must be in DD/MM/YYYY format

## Result Rules

- A student can only have one result document per session and term
- Results cannot be modified if term is finalized
- Subject scores are updated atomically
- Duplicate subjects per result document are rejected

## Term Rules

- Terms are automatically finalized when end date is reached
- Offered subjects must be provided as an array
